## Что именно проверяли

В качестве практической задачи выбрана разработка полезной части самого скилла:

> Сделать локальную утилиту сравнения двух показаний квоты. Различать использованную и оставшуюся долю, не складывать окна, отклонять ошибочные данные и не выдавать сброс счётчика за экономию. Добавить воспроизводимые автоматические тесты.

Задача выполнена в текущем чате с применением `codex-budget`. Во время работы использовались исходные инструкции 0.1.0; уточнения, основанные на этом запуске, вошли в 0.2.0. Параллельно переработаны README, написано руководство и подготовлена публикация.

Это один практический запуск. Отдельная модель для независимой оценки, контрольный запуск без скилла и сравнительная серия A/B не запускались.

## Автоматические проверки

Команда из корня репозитория:

```text
python -m unittest discover -s tests -v
```

Результат первого запуска:

```text
Ran 28 tests in 0.199s

OK
```

Среда: Windows, CPython 3.14; стандартная библиотека, без сторонних зависимостей для утилиты и тестов. 0.199 секунды — время локального набора тестов, **не длительность работы модели и не показатель расхода квоты**.

| Группа | Проверки |
|---|---|
| Арифметика | Процентные пункты, дробные значения, remaining → used |
| Окна квоты | Независимость пятичасового и недельного окон, изменение bucket/длительности |
| Сбросы и время | Изменение reset, наблюдение на границе/после сброса, порядок времени, часовые пояса |
| Неполные данные | Отсутствие времени, reset, показания или окна |
| Невалидные данные | Диапазон, NaN/Infinity, строки, bool, дубликаты, конфликт used/remaining |
| Корректность вывода | Ноль не объявляется бесплатным, уменьшение не обнуляется, посторонние приватные поля не копируются |
| CLI | Чтение JSON с BOM, валидный вывод, безопасная ошибка, сохранность входных файлов |

Исходный код проверок: [test_compare_usage.py](../tests/test_compare_usage.py).

Эти тесты проверяют программу сравнения. Они не означают, что выполнено 28 пользовательских задач с измерением квоты, и не доказывают соблюдение всех инструкций любой моделью.

## Фактические показания

Источник — доступный инструмент статистики Codex. Использовано поле `usedPercent`; остаток рассчитан как `100 − usedPercent`. Время UTC записано сразу после получения показаний, поэтому возможна разница в несколько секунд относительно серверного измерения.

| Контрольная точка | UTC | Пятичасовое: использовано / осталось | Недельное: использовано / осталось |
|---|---|---|---|
| Начало наблюдения | 18:55:01 | 35% / 65% | 6% / 94% |
| После разработки утилиты, тестов и основной документации | 19:02:20 | 58% / 42% | 10% / 90% |
| Наблюдаемая разница | 7 мин 19 сек | **+23 п.п. использовано** | **+4 п.п. использовано** |

Параметры и условия:

- Тариф **Plus** подтверждён инструментом статистики.
- Модель **GPT-6 Astra**, reasoning **High** — сообщены пользователем; инструмент квоты не подтверждает модель или effort.
- Режим скорости неизвестен; Standard не предполагается автоматически.
- Окно 300 минут: одинаковый reset `2026-10-20T20:32:26Z`.
- Окно 10 080 минут: одинаковый reset `2026-10-27T10:12:43Z`.
- Наличие другой активности аккаунта не подтверждено и не исключено.
- Указанные пользователем 66% не использованы как машинная исходная точка: направление того показания не было явно названо, а первая статистика уже показывала 65% остатка.

Сырые ответы инструмента, идентификатор аккаунта и ключи не публикуются. По явному запросу пользователя включены только нормализованные необходимые поля:

- [Начальный снимок](experiments/2026-10-20/before.json)
- [Конечная контрольная точка](experiments/2026-10-20/after.json)
- [Машинный результат сравнения](experiments/2026-10-20/comparison.json)

Воспроизведение арифметики:

```text
python skills/codex-budget/scripts/compare_usage.py docs/experiments/2026-10-20/before.json docs/experiments/2026-10-20/after.json
```

## Что можно заключить

Утилита прошла перечисленные тесты, а доступный счётчик аккаунта вырос на 23 п.п. за указанный интервал. Расход заметный, несмотря на применение экономных инструкций. Большой объём новой документации и работа выбранной модели являются частью выполненной задачи; их отдельный вклад не измерялся.

**Нельзя заключить**, что скилл сэкономил 23%, что это стоимость одних тестов, или что без него расход был бы больше либо меньше. Для этого отсутствует сопоставимая контрольная серия.

Показание сделано внутри активного хода. Оно исключает последующее оформление отчёта, проверки публикации, отправку на GitHub, финальный ответ и ещё не отражённый учёт. Это не финальная стоимость всего обновления 0.2.0. Округление и отложенный учёт дополнительно ограничивают точность.

## Что улучшено по результатам

1. Перед арифметикой явно устанавливается направление used/remaining.
2. Модель и effort помечаются как сообщённые пользователем, если они не проверены отдельно.
3. Показание внутри хода называется контрольной точкой, а не окончательным счётом.
4. Публикация обезличенного отчёта допускается по явному запросу; приватные журналы остаются приватными по умолчанию.
5. Повторяемые проверки арифметики вынесены в локальную утилиту.

## Следующая ступень доказательности

Нужна серия сопоставимых задач с одинаковыми настройками и критериями качества, с навыком и без него. План — в [методике измерений](../skills/codex-budget/references/measurement.md). В этой публикации не приводится прогнозируемый процент экономии.
